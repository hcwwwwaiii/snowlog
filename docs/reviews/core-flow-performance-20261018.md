# 核心流程驗收與首屏載入優化

基線：snowlog-v1 `8ea207dfc885f42a0042a16992687e5729b88a1a`。

## 載入調整

`main.tsx` 不再靜態引入 Supabase SDK；以快取的 dynamic import 在入口執行時開始背景下載，與 React 首次渲染並行。設定讀取及登入恢復重用該 Promise。失敗會清除 Promise 快取，並由既有可恢復錯誤介面處理。沒有改動 SDK 版本、登入／權限邏輯、ResortField、品牌或功能。

不是單純提高 bundle 警告門檻，也不是把 SDK 延至使用者點擊後才下載。SDK 仍在啟動時下載；改善的是首屏的阻塞依賴。第一版在 effect 才開始下載令初始化稍遲，已改為入口執行時就並行啟動，並重新量度。

## 前後對照

同一部電腦、同一瀏覽器、本機 gzip 與 Cache-Control: no-store，交替量度前後各五次。計時程式只存在本機驗證服務，沒有加入正式產品。不是手機慢網或正式 GitHub Pages 的效能保證。

## 真實帳戶與 Storage 驗收

使用者在兩個獨立本機 origin 自行登入既有測試帳戶。測試操作透過正式建置 UI 連接既有 Supabase；沒有用 mock upload，也沒有讀取／輸出憑證。

- A 建立帶本輪標記的行程，B 以邀請碼成功加入並查看共同安排。
- A 上傳一張合成 PNG（320 × 180）及測試 WebM，儲存為私人日誌。照片透過私人 Storage 簽署網址實際載入；B 重新整理後看不到日誌。
- A 分享日誌後，B 可看到內容，下載並放大照片；照片 naturalWidth／naturalHeight 為 320 × 180。
- B 播放影片，readyState 4、error null、播放至結束，時長約 1.096 秒；來源為私人 Storage 簽署網址。
- A 取消分享後，B 重新整理看不到日誌及附件。沒有測試提前撤銷已簽發的網址；既有網址最多十分鐘有效的限制維持不變。
- 最終載入調整後，兩個帳戶重新整理仍能恢復登入；A 的測試日誌保留，B 仍看不到已取消分享的內容。

只新增本輪標記的測試行程、日誌及兩個合成媒體檔案；既有資料沒有修改。測試資料已取消分享；永久清理待使用者當次確認，未宣稱已驗證正式 Storage 刪除。
