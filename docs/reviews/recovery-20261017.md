# 雪場輸入與連線恢復：Grok 交接

Repository：hcwwwwaiii/snowlog；基線 snowlog-v1 ddceef0026a3e79b97caaa52f5193382258bfcb8。

## 改動

- 雪場改用與其他文字欄一致的原生表單值，input 事件只同步目錄來源連結；獨立 datalist ID，保留必填、任意雪場名稱與草稿。避免父層草稿重新渲染回寫受控值。
- 技巧、自評、雪場動態模組使用局部錯誤邊界，15 秒未完成即顯示重試。重試建立新的 lazy instance；若舊版本檔案已失效，可手動重新整理整頁。
- snapshot 讀取有 20 秒外層上限（底層 fetch 維持 15 秒）；逾時或無效回應不取代現有資料，顯示重新載入。
- 啟動連線失敗可重試。Realtime 連線建立／清理失敗不拋出到頁面；失聯時收藏頁保留每 30 秒與 focus 更新。
- 一般讀取及登入逾時不提註冊；只有註冊／重設密碼寄信流程提醒查看信箱。

## 證據與限制

- 修改前，本機兩種輸入方式均能儲存日誌，未重現使用者的雪場失效；不能宣稱已確定是 datalist 或受控輸入造成。此次調整消除受控值回寫途徑，待使用者原本的裝置／輸入方式再確認。
- 修改後，虛構資料驗證了行程自訂雪場、關閉後草稿恢復、空白中文提示、目錄名稱提交，以及日誌覆寫行程預填雪場並成功提交。
- 故障注入驗證資料逾時／無效 snapshot 保留畫面並可重試；模組拒絕／永不完成會顯示局部錯誤；重試元件成功載入。這是實際恢復元件搭配故障 loader，沒有模擬真實 CDN 故障。
- Realtime 使用假 client 檢查 timeout、建立例外、30 秒降級路徑、重新連線及失敗清理，不是正式 websocket 斷線端到端驗證。
- 登入與重設密碼用假 client 驗證逾時文案與模式切換；無真實寄信或密碼變更。
- 型別與正式建置通過；現有主 bundle 超過 500 kB 的提示仍在。沒有重測整站、邀請、分享或正式 Storage 上傳。
- 沒有 SQL、RLS、Auth 或 Storage 設定變更；沒有發布至 gh-pages。原有正式網站繼續使用既有版本。
